FRANCOROUTE — INSTALLATION SUR NETLIFY À PARTIR DE GIT

Commencez par DEMARRER-ICI.txt pour le parcours simplifié.

Le site conserve francoroute.com. L’application couvre le G1, le G2 et le G Full.
Offre : 28 $ CA + taxes, paiement unique, accès de 3 semaines (21 jours).

Ce projet inclut le site, le serveur et les branchements nécessaires. Pour recevoir
les codes de connexion, les notifications de rendez-vous et les paiements réels,
il faut renseigner vos comptes de services. Aucune clé privée n’est incluse.

1. PRÉPARER LE DÉPÔT GIT

Décompressez le ZIP. Copiez les fichiers et dossiers qu’il contient à la racine
DU dépôt prévu pour ce site. Gardez une sauvegarde de votre ancien dépôt.

POUR AJOUTER AVEC LE NAVIGATEUR GITHUB :
- Dans Windows, faites clic droit sur le ZIP, puis « Extraire tout ».
- Ouvrez le dossier extrait jusqu’à voir package.json ET le dossier app.
- Dans GitHub, ouvrez la page principale de votre dépôt, puis Add file > Upload files.
- Glissez ENSEMBLE les dossiers et les fichiers depuis l’Explorateur Windows.
  Le bouton « choose your files » peut vous faire sélectionner seulement les fichiers.
- Vérifiez que la liste contient app/page.tsx et app/layout.tsx avant de valider
  Commit changes sur la branche utilisée par Netlify.
- N’envoyez pas le ZIP lui-même ni son dossier parent : app doit être directement
  à côté de package.json dans GitHub.

Si Netlify affiche « Couldn't find any pages or app directory », le dossier app
n’est pas arrivé à la racine du dépôt construit. Reprenez l’ajout de TOUS les dossiers.
Cette archive a été allégée pour rester sous les 100 fichiers par envoi GitHub.

Le fichier package.json et netlify.toml doivent être à la racine. Conservez aussi
les fichiers commençant par un point, notamment .env.example et .gitignore.

Si vous remplacez l’ancienne version Cloudflare/Sites, retirez de ce dépôt ses
anciens vite.config.*, wrangler.*, cloudflare-env.d.ts, drizzle.config.*, raw.d.ts,
répertoires drizzle, examples, preview, .openai et scripts de déploiement Sites.
Le présent ZIP est autonome. N’y ajoutez pas l’ancien HTML de démonstration.

Ne publiez jamais .env.local, les clés secrètes, node_modules ou .next dans Git.
Ne faites pas un simple glisser-déposer du ZIP sur Netlify : ce projet doit être
construit depuis Git pour exécuter ses fonctions serveur.

2. CRÉER LE PROJET SUPABASE

Utilisez le projet Supabase déjà configuré pour FrancoRoute, ou créez-en un si
aucun projet n’existe. Une fois DATABASE_URL configurée sur Netlify, le déploiement
de production prépare automatiquement les tables de base et Outlook. Aucun
compte, achat ou rendez-vous fictif n’est ajouté. Inutile de copier du SQL.
Les migrations peuvent aussi être exécutées manuellement depuis le SQL Editor :
supabase/schema.sql puis supabase/outlook-pratique.sql.

Relevez :
- SUPABASE_URL : l’URL de votre projet.
- SUPABASE_PUBLISHABLE_KEY : sa clé API publishable (ou l’ancienne clé anon).
  N’utilisez pas une clé secrète ou service_role pour cette variable.
- DATABASE_URL : dans Connect, choisissez Transaction pooler et copiez la chaîne
  complète. Remplacez le mot de passe par le vôtre. Encodez les caractères spéciaux
  du mot de passe dans l’URL. Gardez le nom d’utilisateur et l’hôte fournis.

La connexion vérifie le certificat TLS. Le certificat public Supabase est inclus
dans lib/supabase-ca.mjs et chargé au déploiement comme dans les fonctions Netlify.
Pour les adresses officielles du pooler Supabase ou db.<projet>.supabase.co,
DATABASE_CA_CERT n’est plus utilisé : aucune copie de certificat n’est nécessaire.
La variable reste facultative pour un autre fournisseur de base de données.
Ne désactivez pas la vérification du certificat pour résoudre une erreur.

Dans Authentication, activez le fournisseur Email et autorisez la création des
nouveaux comptes. Le site crée le compte à la première connexion par code.
Définissez la Site URL : https://francoroute.com

IMPORTANT — CODE DE CONNEXION : dans le modèle courriel « Magic Link », remplacez
le lien par le code. Un modèle prêt à coller figure dans
supabase/email-code.html. Il utilise {{ .Token }}.
Le visiteur saisit ce code directement sur /connexion. Aucun mot de passe.
Conservez une durée d’expiration courte adaptée dans les paramètres Email OTP.

Pour envoyer aux clients en production, configurez un SMTP personnalisé dans
Supabase Authentication. Le service de courriel par défaut de Supabase ne suffit
pas pour ouvrir la connexion à tous vos clients. Vous pouvez utiliser Resend SMTP
avec les paramètres fournis dans votre tableau de bord Resend et un expéditeur
sur votre domaine vérifié. Cette configuration SMTP est distincte des variables
Resend de notification ci-dessous.

3. CONFIGURER LES COURRIELS DE RENDEZ-VOUS AVEC RESEND

Dans Resend, vérifiez un domaine ou sous-domaine que vous contrôlez, par exemple
notifications.francoroute.com, en ajoutant les enregistrements DNS demandés.
Préservez les enregistrements existants nécessaires à votre messagerie.

Créez une clé API d’envoi, puis relevez :
- RESEND_API_KEY : votre clé privée Resend.
- BOOKING_MAIL_FROM : un expéditeur autorisé sur ce domaine vérifié, par exemple
  FrancoRoute <rendezvous@notifications.francoroute.com>.
- BOOKING_NOTIFY_EMAIL : francoroute@outlook.com

L’adresse Outlook est le DESTINATAIRE, pas l’expéditeur vérifié Resend.

Quand un visiteur réserve, le courriel vous donne la date, le nom et le numéro
à appeler. Vous téléphonez au client à l’heure de l’appel de 15 minutes.
Le client reçoit sa confirmation à l’écran et peut ajouter le rendez-vous à son
calendrier. Le site n’envoie pas de courriel de confirmation au client.

La réservation reste enregistrée si le courriel échoue. Dans /gestion, regardez
la colonne de notification et utilisez le bouton pour retenter l’envoi.
Consultez toujours /gestion avant d’appeler : les annulations y sont visibles.

4. CONFIGURER STRIPE

Dans votre compte Stripe, relevez STRIPE_SECRET_KEY.
Ajoutez un endpoint webhook :
https://francoroute.com/api/stripe-webhook

Activez ces événements :
- checkout.session.completed
- checkout.session.async_payment_succeeded
- charge.refunded

Copiez le secret de signature de cet endpoint dans STRIPE_WEBHOOK_SECRET.
Aucun produit à créer manuellement : le serveur crée la ligne 28 CAD + taxes / 21 jours
lors de l’ouverture de Stripe Checkout.

Définissez PAYMENT_TAX_MODE=exclusive : les taxes applicables s’ajoutent
aux 28 CAD. Stripe Tax et vos paramètres fiscaux doivent être configurés.
Cette version ne propose pas de paiement sans taxes ni de prix taxes incluses.

Utilisez d’abord les identifiants Stripe de test pour votre vérification interne,
puis les clés et le webhook de production avant d’accepter des clients.
Le site public ne contient pas de mode de démonstration ni d’accès gratuit caché.

5. CONNECTER GIT À NETLIFY

Importez votre dépôt Git dans Netlify, ou mettez à jour votre projet Netlify
existant si c’est celui que vous souhaitez garder.

Réglages :
- Base directory : vide si package.json est à la racine.
- Build command : celle du fichier netlify.toml (réparation des dossiers,
  compilation, puis préparation automatique de la base)
- Publish directory : .next
- Node.js : 22 (déjà déclaré dans netlify.toml).

Netlify installe automatiquement l’adaptateur Next.js. Ne choisissez pas une
publication du dossier public, une exportation statique, ni une règle universelle
redirigeant toutes les pages vers index.html.

Dans Environment variables, ajoutez les valeurs listées dans .env.example.
Rendez-les accessibles aux fonctions serveur ; gardez les clés privées secrètes.
DATABASE_URL doit également être disponible pour Builds en contexte Production.
Pour Supabase, DATABASE_CA_CERT n’est pas nécessaire. Ne fournissez pas les secrets de production
aux Deploy Previews ou aux Branch deploys.
SITE_ORIGIN doit être https://francoroute.com, sans barre oblique finale.
ADMIN_EMAILS est prérempli avec nellyfolefack6@gmail.com. Modifiez-le si vous
préférez une autre adresse de gestion. Plusieurs adresses peuvent être séparées
par une virgule. Chacune doit se connecter et vérifier son courriel.

Les changements de variables nécessitent un nouveau déploiement.
Utilisez un jeu de comptes et de clés distinct pour un éventuel site de staging.

6. GARDER FRANCOROUTE.COM

Dans Netlify, ajoutez francoroute.com comme domaine principal et suivez les
instructions DNS affichées pour VOTRE site. Activez HTTPS et la redirection
www vers votre domaine principal. Ne changez pas d’adresse vers un domaine .ca.

Si francoroute.com est déjà relié à ce projet Netlify, gardez cette liaison.
Si vous vérifiez d’abord sur une URL .netlify.app, configurez SITE_ORIGIN et le
webhook pour cette URL de vérification, puis remettez-les sur francoroute.com
au moment de la mise en ligne définitive.

7. OUVRIR L’AGENDA ET VÉRIFIER LES BRANCHEMENTS

- Ouvrez https://francoroute.com/gestion.
- Connectez-vous avec le courriel inscrit dans ADMIN_EMAILS, puis le code reçu.
- Ajoutez vos créneaux de 15 minutes. Les horaires sont ceux de l’Est.
  Les clients ne voient que les créneaux ouverts, avec au moins 2 heures de préavis.
- Effectuez une réservation de contrôle avec vos propres coordonnées.
  Vérifiez le rendez-vous dans /gestion et le courriel dans votre boîte Outlook.
  Annulez cette réservation avec son lien avant d’ouvrir au public.
- Vérifiez la connexion, le paiement Stripe de test et l’ouverture de l’application
  dans un compte client distinct. Le compte de gestion a un accès administrateur
  et ne sert donc pas à vérifier la restriction payante.
- Remettez les clés Stripe de production puis redéployez. Vérifiez le webhook.

Après validation de cette nouvelle version, retirez ou protégez l’ancienne
application francoroute-prepa.netlify.app si elle permet encore un accès public
au contenu. Le présent ZIP ne modifie pas cet autre projet Netlify.

Ces dernières vérifications nécessitent vos comptes réels et n’ont pas été
réalisées lors de la préparation du ZIP. Les tests locaux utilisent PostgreSQL
et simulent les réponses des services externes, sans envoyer de messages ni payer.

À RETENIR

Vous recevrez les notifications de réservation après la configuration Resend.
Le ZIP seul ne connecte pas votre boîte mail ni votre compte bancaire.
Le calendrier se synchronise avec Outlook après les étapes d’ACTIVER-OUTLOOK.txt.
Il n’est pas relié à Google Calendar et n’envoie pas de rappels automatiques.

Pour suivre le site : /gestion.
Pour les clients et la préparation : /espace.
Pour réserver un premier appel : /reserver.
